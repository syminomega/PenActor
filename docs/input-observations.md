# Pencil 起笔压力观察

## 当前证据

2026-10-21，用户在 Photoshop 2026 中使用 Sidecar Pencil，暂停监听后保留了 300 条事件。通过当时的事件表人工核对三次落笔，显示值经过界面四位小数格式化，下面不是完整精度原始 JSON：

| 落笔时间 | mouseDown 压力 | 后续部分采样（省略重复值） |
| --- | --- | --- |
| 19:11:17 | 0.0784 | 0.0745 → 0.0902 → 逐渐升高 |
| 19:11:18 | 0.0784 | 0.0706 → 0.0784 → 0.0667 → 0.0588 → 再升高 |
| 19:11:19 | 0.0784 | 0.0471 → 0.0235 → 0.0118 → 再升高 |

采集代码直接读取 NSEvent.pressure，不填充 0.0784 默认值，也不做压力映射。第三笔存在显著的起笔压力回落，与用户截图中的起点圆头、随后变细现象相符。第一条接触事件非零本身不能证明异常，三笔相同起始值也不足以确认硬件、Sidecar 初始化或某个估计值机制就是根因。当时界面未显示毫秒时间，不能从该表判断持续时长；不要将三笔未经核实地对应到截图的左右位置。

## VoidLink 资料

用户提供的 [关于 Drawing Toolkit（绘画进阶套件）](https://voidlink.yuque.com/org-wiki-voidlink-znirha/biuzs1/sl96pxao4a0oid1x)中，“笔迹瑕疵优化”段明确说明开发者已过滤笔迹开头的异常力度点，并要求使用相应版本、HD 笔迹和压力曲线开关；文中也说明压力曲线模块附带笔迹优化和过滤。

这是另一个 Pencil 串流链路存在相似问题并实施修正的直接开发者说明，支持本项目将起笔阶段修正作为待研究功能。但该页面没有公布完整采样、算法或与 Sidecar 的对照，不能据此证明两者根因相同，也不能把 Windows 端效果直接视为 macOS PS/CSP 兼容性证据。本文仅参考行为描述，不复制第三方实现。

## CSP 的可能影响

CSP 官方说明提供以下独立控制：

- [Correction](https://help.clip-studio.com/en-us/manual_en/810_subtools/C.htm)：Stabilization 与 Post correction 调整线条平滑和后修正。
- [Starting and ending](https://help.clip-studio.com/en-us/manual_en/810_subtools/S.htm)：可让笔画起点从配置的最小值逐渐变化，并作用于所选笔刷参数。
- [Brush dynamics](https://help.clip-studio.com/en-us/manual_en/240_brushes/Customizing_brush_tools.htm)：笔刷大小等参数可以使用自己的笔压曲线和最小值。

因此 CSP 中不易观察到问题，可能与具体笔刷的起笔效果、笔压曲线、最小尺寸、点间距或应用输入处理有关。目前未检查用户的 CSP 参数，也没有配对日志，不能认定 CSP 必定过滤了这一压力尖峰；普通位置防抖不等于压力滤波。

建议用副本笔刷做对照：记录当前参数，再分别关闭起笔 / 收笔、后修正和防抖，设置可比较的压力曲线与最小尺寸，重复轻压和正常起笔，分别导出 PS / CSP 日志。若系统事件两边都有相同起笔回落而只有 PS 显示圆头，则应用 / 笔刷处理差异得到更强支持；还需通过逐项参数对照确定原因。不要在证据不足时把每笔第一点强制归零，以免破坏点画和有意重压起笔。

## 压力重映射的初步实机反馈

2026-10-21，用户重新运行 PenActor 0.2.0（实现提交 `b9d2cba`）后反馈压力重映射「确实生效了」。这支持当前环境中 Quartz 主动事件 tap 改写压力可以影响实际绘画响应。此次反馈未逐项记录具体应用、曲线及笔刷参数，不扩展为 PS / CSP 全部组合通过，也不表示此前的起笔压力回落已得到修复。

事件链路、设备 / 应用筛选、曲线计算和证据边界见 [压力重映射技术说明](pressure-remapping.md)。
