# 轨迹平滑与分项继承（0.6.0）

配置 → 选择设备 → 设备默认中，可以启用“平滑输入”并调节强度。默认关闭，强度初始为 35%。只有启用了配置、且命中配置中指定应用的笔输入才会被处理。

应用行的设置按钮可分别选择压力曲线、入锋、出锋、轨迹平滑。各项默认继承设备默认；取消某项的“继承设备默认”会复制当前有效值供单独编辑。再次继承后会继续跟随设备默认更新。关闭“在此应用中处理输入”使整个应用透传。修改后需保存配置，从下一笔生效。

例如，只在 Photoshop 增加平滑：打开该应用的设置，选择轨迹平滑，取消继承，启用平滑；压力曲线、入锋、出锋保持继承。设备默认修改时，这三项仍自动跟随。

## 处理方式

采用 One Euro 自适应低通滤波，使用事件自身时间间隔，而非界面刷新周期。用屏幕点速度估算快慢，用同一滤波系数分别处理屏幕坐标及数位板绝对 X/Y，保留各自单位。鼠标形式与独立 tablet 形式各自保存滤波状态，避免混合两种事件形式造成坐标跳变。

强度 s ∈ [0,1]：最小截止频率为 12×0.1^s Hz，速度系数为 0.08×(1−s)+0.005，速度估算的截止频率为 1 Hz。首点直通；重复或倒退时间保持上一结果，超过 250 ms 的间隔重新初始化。强度为零等同关闭。

本功能只修改落笔位置，不额外等待后续点，不插入更多事件。平滑本身仍会产生跟随偏差，强度越高越可能圆化转角。0.6.1 为兼容真实应用，不再重写按下／松开事件的位置及位移字段，只修改接触中的移动事件。抬笔压力仍为零，不补画尾线；光标可能回到实际抬笔位置。悬停、普通鼠标、右键、触控手势不做轨迹平滑。

压力曲线和笔锋处理与位置滤波独立，入锋距离仍用输入坐标计算。出锋开启时继续使用已有尾部缓存，它本身会增加延迟；轨迹平滑不再叠加缓存。暂停、禁用会恢复尚未输出的原始缓存事件并清理滤波状态。

## 配置与导出

- profiles.json 升为 schema 5，defaults.json 升为 schema 3。旧配置自动备份到 Application Support/PenActor/Backups 后迁移。
- 应用规则的 overrides 为 curve、entry、exit、smoothing 的集合；inherit 全部继承，custom 按集合覆盖，passthrough 整体透传。
- 旧 custom 迁移为覆盖前三项，新增平滑继承默认关闭；继承、透传原行为不变。
- 导出升为 schema 3；tap 诊断增加 eventType、inputPosition/outputPosition 和可选 smoothing（含两种数位板坐标）。修改计数也包括位置变化。保留两类事件流各 500 条，不建立一一关联。

Apple 说明 AppKit 默认合并鼠标移动、拖动与 tablet 事件：[isMouseCoalescingEnabled](https://developer.apple.com/documentation/appkit/nsevent/ismousecoalescingenabled)。这与 tap 和应用层频率不同相符，但不能确认 Photoshop 内部最终消费多少点。软件的 60 Hz UI 发布只控制显示，原记录在该定时器之前逐事件采集。

## 实机待验收

在相同应用、笔刷、画布缩放和映射状态下对两支笔复测。分别比较关闭、低强度、高强度的直线、慢曲线、快速折线、点画及抬笔；观察 PS/CSP 是否采用修改后的坐标，以及是否有终点回跳或明显拖尾。再测试平滑与入锋、出锋分别及同时开启。未完成这些实测前，不宣称修复 Sidecar 兼容性。

## 0.6.1 兼容修正与待验证项

用户实测：0.6.0 开启 Photoshop 的轨迹平滑后无法绘画；暂停映射或只关闭平滑即可恢复。故障快照中仍有连续拖动与非零输出压力，出锋关闭且缓存为零。因此问题已定位到平滑开启路径，但还不能确认是哪个底层字段导致 PS 拒绝笔画。

初版会对落笔和抬笔也执行位置及位移写入，包括首点没有位移的情况。0.6.1 收紧为仅在中间移动点确实改变时写入坐标；落笔只初始化滤波器，按下／松开的位置、位移、点击状态等保持原样，压力仍按原来的曲线和笔锋处理。增加真实 AppKit 事件往返的边界字段回归。此修正仍须 PS/Sidecar 实测确认，不能以进程内模拟替代。

## 0.6.2 安全回退：轨迹平滑暂不可用

用户进一步实测 0.6.1 仍出现跨画布直线和瞬移，保留按下／松开字段不足以解决问题。因此生产运行已完全停止所有位置和位移改写，即使已保存的平滑配置开启，也只处理原有压力曲线与笔锋。界面明确标记平滑暂不可用，保留参数，诊断用 smoothingBypassReason 说明旁路原因。分项继承继续可用。

不能再把进程内合成事件通过测试当作 Photoshop 已兼容。下一步先分析真实事件序列化样本，再确定是否要更换 tap 层级或采用不同坐标输出方式；目前没有足够证据把根因归结到某个字段。

为复现真实 Sidecar 包，命中已启用设备和应用时，在压力处理之前保留少量 Quartz event.data：各设备每种事件形式一份，合计最多 16 份，只在内存中保留；手动导出后以 mapping.coordinateProbes 的 Base64 eventData 保存。仅包含识别出的数位笔点事件，不包含键盘、普通鼠标或手指触摸；可能含设备标识、坐标、窗口／进程信息，因此日志仍应按本地诊断文件处理。清空记录同时清空这些样本。

这些数据供 CGEvent(withDataAllocator:data:) 在进程内检查字段和不同改写操作的副作用，不向真实应用重新投递。测试可显式启用候选坐标变换以验证算法，但生产默认禁止坐标写入，并有单独回归检查这一安全边界。
