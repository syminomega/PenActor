# 入锋与出锋修正（0.3.0 实验版）

0.4.0 保留本文输入处理机制，新增 [菜单栏与分页设置](preferences.md)，硬件配置文件保存为 schema 3，兼容 schema 1 / 2。

本版在设备压力曲线之后增加笔画包络。入锋可以在实时事件上完成；用户选择了“允许缓存并延迟笔迹、抬笔后回看尾部”的出锋方式，因此启用出锋时会暂存笔事件，再通过 Quartz 重发。

这改变了 0.2.0 只有“修改并返回原事件”的路径。关闭出锋时仍直接修改并返回事件；启用出锋的匹配笔画才使用缓冲。两项默认关闭，旧配置迁移后不会自动改变原有笔压响应。

## 配置与建议测试

在设备配置编辑器中：

| 选项 | 默认值 | 含义 |
| --- | --- | --- |
| 入锋 | 关闭 | 让接触开始的输出压力从零渐入 |
| 入锋长度 | 12 屏幕点 | 累计移动距离达到此值时恢复曲线输出；不是画布像素，不随画布缩放换算 |
| 过渡时间上限 | 60 ms | 静止或缓慢移动时也能随后续采样恢复压力；长度与时间先达到者生效 |
| 出锋 | 关闭 | 暂存尾部事件，抬笔后将未输出的末段渐隐到零 |
| 出锋时长 / 延迟 | 60 ms | 尾部修整的时间范围，同时也是匹配笔事件的基础输出延迟，可调 10～200 ms |

点击“入锋 / 出锋测试预设”会同时打开两项并设置上述数值，需要再保存并启用配置。设置在下一笔生效，停止 / 禁用立即中断当前缓冲。

先用同一笔刷比较：全部关闭 → 只开入锋 → 再开出锋。检查快速轻划、慢速加压、突然抬笔、短点画、连续落笔和快捷键。出锋延迟过于明显时减小到 20～40 ms；入锋消减过多时缩短长度或时间，或单独关闭入锋。

非常短的点画或线段可能变淡甚至消失，因为首尾包络会重叠。当前没有额外的短点画保留算法。静止按住而系统不继续发采样时，程序不会合成压力采样来恢复点画。

交互参考了 CSP 的 [Starting and ending](https://help.clip-studio.com/en-us/manual_en/810_subtools/S.htm)：分别启用首尾效果并调节范围。CSP 能在应用内部按笔刷参数、长度或百分比处理；PenActor 当前修改系统事件压力，出锋按时间窗口实现，没有实现完整的 CSP 笔刷引擎。

## 计算顺序

```text
驱动 / Sidecar 压力
    → 已配置的静态压力曲线
    → 入锋系数
    → 缓冲出锋系数
    → 系统字段量化后的输出压力
```

设 `S(u) = u² × (3 − 2u)`，输入 `u` 限制在 `[0,1]`。

入锋进度为：

```text
u = clamp(max(累计屏幕距离 / 入锋长度, 已过时间 / 时间上限), 0, 1)
入锋系数 = S(u)
```

首次接触的距离和经过时间均为零，因此入锋系数为零。后续逐步恢复至 1。时间倒退的采样不倒退已取得的入锋进度；独立数位笔和带 tablet subtype 的鼠标事件共享同一设备笔画的进度，两种压力字段分别计算曲线。

启用出锋后，事件先按曲线和入锋处理，再进入队列。设抬笔事件时间为 `T`、待发采样时间为 `t`、出锋时长为 `D`：

```text
v = clamp((T − t) / D, 0, 1)
出锋系数 = S(v)
最终压力 = 曲线输出 × 入锋系数 × 出锋系数
```

例如仍未输出的三条恒定压力采样距离抬笔分别为 60、30、0 ms，出锋时长为 60 ms，其出锋系数分别为 1、0.5、0。即便原始压力没有提前下降，也可以修整缓冲区里的尾部。

已发送的采样不会被撤销或修改。如果 Sidecar 合并 / 延迟了一批事件，导致抬笔到达时部分尾部已发送，则只能修整尚在队列中的部分。窗口越长，通常保留的尾部越多，但输入延迟也越大。

## 输出时序

`BufferedPenEvents` 按接收顺序保存事件副本；队列中的事件由主动 tap 暂时返回 `nil` 阻止继续传递。专用 RunLoop 每约 2 ms 检查到期事件并排空队首，正常情况下每个匹配笔事件至少等待所设出锋时长。

不同设备或配置使用不同延迟时仍维持全队列的接收顺序，后面的短延迟事件可能等待更久。调度负载也会带来额外等待，不保证严格固定的总延迟。

输出副本通过 `.cgAnnotatedSessionEventTap` 重发，保留原有位置、目标 PID、时间戳、倾斜、旋转和按钮字段。为了避免自己的 tap 再次拦截，重发事件的 `eventSourceUserData` 写入 PenActor 标记 `0x50454E4143544F52`；这是相对于原事件的一项明确元数据变化。本项目的 tap 见到标记后直接放行。

缓冲的按下、拖动、释放和关联的移动 / proximity 事件维持顺序。先出现零压力采样、稍后才出现普通鼠标释放时，会继续保持释放关联，避免释放越过尚未输出的按下事件。感应范围退出而缺失释放时，会尝试补发零压力释放，结束已缓存或已输出的按钮接触。

只在设备和目标应用匹配时建立缓冲。未知设备、没有可解析目标的初始事件及未配置的 Wacom 保留原压力。关联设备的 proximity / 移动事件可能一起延迟，以保持事件顺序。

## 暂停、快捷键与故障

输出通过独立的锁串行化，避免“定时输出、用户暂停、重新启动”互相穿插。

- 暂停、停止监听、禁用设备配置：按顺序排空缓存，相关设备的待发压力恢复为原值，再对已输出或即将输出但缺少释放的按下事件补发必要的零压力释放。本笔可能因此提前结束，下一笔重新开始。
- 快捷键或修饰键变化：先排空已有事件，再转发该边界事件；本笔后续绕过出锋缓冲，避免已按下的快捷键跑到延迟笔画前面。键盘事件不参与压力计算，也不写入诊断日志。
- 目标应用变化或不相关的鼠标按下：提前排空，必要时释放旧接触，再转发边界事件，避免旧应用继续接收滞留笔画。
- 缓冲达到 2048 条：提前排空，不丢弃按下 / 抬起，本笔改为直接输出。
- tap 超时、系统停用、事件线程结束：停止映射，尝试排空与释放，不自动反复重启。系统撤销权限后能否投递释放仍受系统限制。

正常出锋通过已有事件进行包络计算，不额外延长绘画轨迹；合成释放只用于缺失释放、取消和恢复。不会在抬笔后沿旧方向继续补画一段线。

## 配置与诊断

配置 JSON 升级至 schema 2，读取时兼容 schema 1。旧配置没有 `taper` 字段时，补上默认关闭的设置；保存采用原子写入。应用启动仍不自动启用映射。

```json
"taper": {
  "entryEnabled": true,
  "entryDistance": 12,
  "entryDurationMS": 60,
  "exitEnabled": true,
  "exitDurationMS": 60
}
```

导出日志仍为 schema 2，新增字段为兼容性扩展：

- `mapping.bufferedEventCount`：导出时尚未输出的事件数。
- `mapping.diagnostics[].delivery`：直接输出、延迟输出或提前排空；诊断在准备输出时写入，未发出的事件尚不在这个列表里。
- `mapping.diagnostics[].taper`：静态曲线结果、入锋系数、出锋系数、入锋累计距离与经过时间、处理阶段。

输出压力记录的是字段写入后读回的数值。它证明程序准备了什么事件，不等于目标应用已确认接收。没有 tablet 元数据的释放、辅助 proximity 或恢复用的合成释放不强行伪装成数位笔压力诊断，因此不能用诊断条数反推全部输出事件数。
